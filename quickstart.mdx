This guide gets Weaviate running locally with Docker, inserts sample data, and runs a semantic search — all in under five minutes.

<Steps>
  <Step title="Start Weaviate with Docker">
    Create a `docker-compose.yml` file that starts Weaviate and a local text embedding service:

    ```yaml docker-compose.yml
    services:
      weaviate:
        image: cr.weaviate.io/semitechnologies/weaviate:1.36.0
        ports:
          - "8080:8080"
          - "50051:50051"
        environment:
          ENABLE_MODULES: text2vec-model2vec
          MODEL2VEC_INFERENCE_API: http://text2vec-model2vec:8080

      # Lightweight embedding model — generates vectors from objects during import
      text2vec-model2vec:
        image: cr.weaviate.io/semitechnologies/model2vec-inference:minishlab-potion-base-32M
    ```

    Start both services:

    ```bash
    docker compose up -d
    ```

    Weaviate listens on port `8080` (REST/GraphQL) and `50051` (gRPC). The `text2vec-model2vec` service runs the `minishlab/potion-base-32M` model locally and generates vector embeddings during import.

    <Note>
      The `text2vec-model2vec` vectorizer is a lightweight, fully local option that requires no API keys. You can swap it for any other vectorizer module — `text2vec-openai`, `text2vec-cohere`, `text2vec-huggingface`, and many others. See [Modules / Vectorizers](/modules/vectorizers) for the full list.
    </Note>
  </Step>

  <Step title="Install the Python client">
    ```bash
    pip install -U weaviate-client
    ```

    The Python client wraps both the REST and gRPC APIs. Other official clients are available for TypeScript, Java, Go, and C#.
  </Step>

  <Step title="Connect to Weaviate">
    ```python
    import weaviate

    client = weaviate.connect_to_local()
    print(client.is_ready())  # True
    ```

    `connect_to_local()` connects to `http://localhost:8080` (REST) and `localhost:50051` (gRPC) using the defaults from your Docker Compose setup.
  </Step>

  <Step title="Create a collection">
    Define a collection called `Article` with a `content` text property. The `text2vec_model2vec()` vectorizer configuration tells Weaviate to automatically generate embeddings for each object using the local model service.

    ```python
    from weaviate.classes.config import Configure, DataType, Property

    client.collections.create(
        name="Article",
        properties=[
            Property(name="content", data_type=DataType.TEXT),
        ],
        vector_config=Configure.Vectors.text2vec_model2vec(),
    )
    ```

    The collection is now ready to accept objects. Weaviate will call the `text2vec-model2vec` inference service to generate a vector for every inserted object.
  </Step>

  <Step title="Insert data">
    Insert three example objects. Weaviate calls the embedding model automatically and stores both the object and its vector.

    ```python
    articles = client.collections.get("Article")

    articles.data.insert_many([
        {"content": "Vector databases enable semantic search"},
        {"content": "Machine learning models generate embeddings"},
        {"content": "Weaviate supports hybrid search capabilities"},
    ])

    print("Inserted 3 articles")
    ```

    `insert_many` is a batched operation. The Python client sends objects to the gRPC batch endpoint for high throughput.
  </Step>

  <Step title="Run a semantic search">
    Query the collection using `near_text`. Weaviate vectorizes the query string with the same model and returns the closest matching object.

    <CodeGroup>

    ```python Python
    results = articles.query.near_text(
        query="Search objects by meaning",
        limit=1,
    )

    print(results.objects[0].properties)
    # {'content': 'Vector databases enable semantic search'}
    ```

    ```bash curl
    curl -X POST http://localhost:8080/v1/graphql \
      -H "Content-Type: application/json" \
      -d '{
        "query": "{
          Get {
            Article(
              nearText: { concepts: [\"Search objects by meaning\"] }
              limit: 1
            ) {
              content
            }
          }
        }"
      }'
    ```

    </CodeGroup>

    The result is `"Vector databases enable semantic search"` — the object whose meaning is closest to the query, even though it shares no keywords with `"Search objects by meaning"`.
  </Step>

  <Step title="Close the client">
    Always close the client when finished to release gRPC connections:

    ```python
    client.close()
    ```
  </Step>
</Steps>

## Complete example

The full end-to-end script from the steps above:

```python
import weaviate
from weaviate.classes.config import Configure, DataType, Property

# Connect to Weaviate
client = weaviate.connect_to_local()

# Create a collection
client.collections.create(
    name="Article",
    properties=[Property(name="content", data_type=DataType.TEXT)],
    vector_config=Configure.Vectors.text2vec_model2vec(),
)

# Insert objects and generate embeddings automatically
articles = client.collections.get("Article")
articles.data.insert_many([
    {"content": "Vector databases enable semantic search"},
    {"content": "Machine learning models generate embeddings"},
    {"content": "Weaviate supports hybrid search capabilities"},
])

# Perform semantic search
results = articles.query.near_text(query="Search objects by meaning", limit=1)
print(results.objects[0].properties)

client.close()
```
