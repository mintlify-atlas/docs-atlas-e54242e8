Weaviate is an open-source, cloud-native vector database written in Go. It stores both objects and their vector embeddings, combining vector similarity search with keyword filtering, retrieval-augmented generation (RAG), and reranking in a single query interface.

## What is Weaviate?

Weaviate is a vector database purpose-built for AI applications. Unlike traditional databases that store and query structured data, Weaviate stores vector embeddings alongside objects and uses approximate nearest-neighbor (ANN) algorithms to find semantically similar content at scale.

Every object in Weaviate has:
- **Properties** — structured data fields with typed values (`text`, `int`, `date`, `uuid`, `geoCoordinates`, and more)
- **Vectors** — high-dimensional float arrays that capture semantic meaning, generated by a vectorizer module or provided directly

Weaviate can automatically generate vectors at import time using integrated model providers — OpenAI, Cohere, HuggingFace, Google, and others — or accept pre-computed embeddings you supply yourself.

## Key use cases

**Semantic search** — Find documents, products, or records by meaning rather than exact keyword matches. A query for "vehicle maintenance" returns results about "car repair" even without shared keywords.

**Retrieval-augmented generation (RAG)** — Retrieve relevant context from your data and pass it to an LLM to generate grounded, accurate answers. Weaviate's built-in generative modules let you run RAG queries directly from the database without additional orchestration.

**Recommendation engines** — Find similar items using vector proximity. Given a product, article, or user profile, retrieve the nearest neighbors in embedding space.

**Image search** — Use multimodal modules (`multi2vec-clip`, `multi2vec-bind`) to search images by text query or by visual similarity to another image.

**Hybrid search** — Combine vector similarity with BM25 keyword search for best-of-both results, tunable with the `alpha` parameter.

## Architecture overview

Weaviate follows a **hexagonal (ports-and-adapters) architecture** with a clean separation between the API layer, business logic, and storage:

```
cmd/weaviate-server/     → Entry point
adapters/
  handlers/
    rest/                → REST API (go-swagger generated)
    grpc/                → gRPC API (search, batch, aggregation)
    graphql/             → GraphQL API
  repos/
    db/                  → Storage implementation
      lsmkv/             → Custom LSM key-value store
      vector/            → Vector indexes (HNSW, flat, dynamic)
usecases/                → Business logic
entities/                → Domain models and shared types
modules/                 → Vectorizer, generative, reranker plugins
cluster/                 → RAFT consensus, replication, sharding
```

The database is built in Go for speed and reliability. The storage layer uses a custom LSM (Log-Structured Merge-tree) key-value store with three bucket strategies: `Replace` (classic KV), `Set` (inverted index), and `Map` (BM25 term frequencies).

### APIs

Weaviate exposes three API protocols:

| API | Port | Use |
|-----|------|-----|
| REST | `8080` | Schema management, object CRUD, batch operations |
| gRPC | `50051` | High-performance search and batch import |
| GraphQL | `8080` | Flexible `Get` and `Aggregate` queries |

### Storage: DB → Index → Shard → Store

Each collection maps to an **Index**, which manages one or more **Shards**. Each shard contains:
- An LSM store for objects and properties
- One or more vector indexes (HNSW, flat, or dynamic)
- An inverted index for keyword filtering

### Vector indexes

- **HNSW** — The primary index. Supports PQ/BQ/SQ compression and multi-vector. Scales to billions of vectors.
- **Flat** — Brute-force search for small datasets. No build overhead, exact results.
- **Dynamic** — Starts as flat, automatically switches to HNSW as data grows.

### Distributed operation

Weaviate uses **RAFT consensus** for schema changes and cluster coordination. Data is distributed across nodes using consistent hashing, and replication factor is configurable per collection.

## Module system

Weaviate's functionality is extended through a plugin module system. Modules implement a common `Module` interface and register HTTP handlers, vectorization logic, generative capabilities, or reranking. There are approximately 67 modules covering:

- **Vectorizers** — `text2vec-openai`, `text2vec-cohere`, `text2vec-huggingface`, `text2vec-model2vec`, `multi2vec-clip`, and more
- **Generative** — `generative-openai`, `generative-cohere`, `generative-anthropic`, `generative-google`, and more
- **Rerankers** — `reranker-cohere`, `reranker-jinaai`, `reranker-voyageai`, and more
- **Backup providers** — `backup-s3`, `backup-gcs`, `backup-azure`, `backup-filesystem`

<Note>
  You choose which modules to enable at startup via the `ENABLE_MODULES` environment variable. Only enabled modules consume resources.
</Note>
