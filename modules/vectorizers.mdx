Vectorizer modules integrate with embedding models to automatically generate vector representations of your data. When you insert an object, Weaviate sends the configured properties to the vectorizer and stores the resulting embedding alongside the object. When you run a `nearText` or `nearImage` query, Weaviate vectorizes the query using the same module so distances are computed in the same space.

## How vectorizers work

Vectorizers operate at two points in the data lifecycle:

1. **Import time** — When you insert an object, Weaviate extracts the text from properties marked for vectorization and sends them to the embedding model API. The returned vector is stored in the HNSW or flat index alongside the object.
2. **Query time** — When you run a `nearText` or `nearImage` query, Weaviate vectorizes the query string with the same module. This ensures that the query vector lives in the same embedding space as the stored vectors, making distance comparisons meaningful.

When no vectorizer is configured (`none`), you must supply the vector yourself with each inserted object and each query.

## Enabling a vectorizer module

Set the `ENABLE_MODULES` environment variable when starting Weaviate, then configure the module per collection in the schema.

```bash
docker run -p 8080:8080 -p 50051:50051 \
  -e ENABLE_MODULES=text2vec-openai \
  -e OPENAI_APIKEY=your-api-key \
  cr.weaviate.io/semitechnologies/weaviate:latest
```

You can enable multiple modules at once by separating them with commas:

```bash
-e ENABLE_MODULES=text2vec-openai,text2vec-cohere,multi2vec-clip
```

## Image vectorizer

The `img2vec-neural` module vectorizes images only, using a neural network image encoder deployed locally.

| Module | Description | Config |
|--------|-------------|--------|
| `img2vec-neural` | Encode images to vectors using a local ResNet model | `IMAGE_INFERENCE_API` |

## Configuring a vectorizer in a collection

Specify the vectorizer when you create a collection. The configuration is stored in the schema and applied to every object imported into that collection.

<AccordionGroup>
  <Accordion title="OpenAI (text2vec-openai)">
    ```python
    import weaviate
    from weaviate.classes.config import Configure, Property, DataType

    client = weaviate.connect_to_local()

    client.collections.create(
        name="Article",
        properties=[
            Property(name="title", data_type=DataType.TEXT),
            Property(name="body", data_type=DataType.TEXT),
        ],
        vector_config=Configure.Vectors.text2vec_openai(
            model="text-embedding-3-small",
        ),
    )
    ```

    Set your API key before starting Weaviate:

    ```bash
    export OPENAI_APIKEY=sk-...
    ```
  </Accordion>

  <Accordion title="Cohere (text2vec-cohere)">
    ```python
    client.collections.create(
        name="Article",

            Property(name="title", data_type=DataType.TEXT),

            model="embed-english-v3.0",
    ```

## API key configuration

Pass API keys as environment variables when starting Weaviate. Never hard-code keys in your schema or application code.

```bash
docker run -p 8080:8080 -p 50051:50051 \
  -e ENABLE_MODULES=text2vec-openai,generative-openai \
  -e OPENAI_APIKEY=sk-... \
  cr.weaviate.io/semitechnologies/weaviate:latest
```

You can also pass a key per-request in the client if you want users to supply their own keys:

```python
import weaviate
from weaviate.classes.init import Auth

client = weaviate.connect_to_local(
    headers={"X-OpenAI-Api-Key": "sk-..."}
)
```

<Note>
  Weaviate reads API keys from environment variables at startup. If you rotate a key, restart the Weaviate container with the new value.
</Note>
